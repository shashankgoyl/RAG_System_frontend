# ConvoRAG – Conversation Intelligence System

Full-stack RAG chatbot that processes conversation CSV data, builds topic & message checkpoints, extracts a user persona, and serves a chat interface.

**Stack:** FastAPI · LangChain · Groq (LLaMA 3.3 70B) · Scikit-learn · React · Tailwind CSS  
**Deploy:** Render (backend) · Netlify (frontend)

## Local Development (Full Setup)

### 1 — Prerequisites

- Python 3.10+
- Node.js 18+
- A free Groq API key → https://console.groq.com

### 2 — Backend

```bash
cd backend

# Install dependencies
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Create .env
echo "GROQ_API_KEY=gsk_your_key_here" > .env

# Place the CSV
mkdir -p data
cp /path/to/conversations.csv data/

# Start the server
uvicorn main:app --reload --port 8000
```

Verify: http://localhost:8000/api/health → `{"status":"ok"}`  
Swagger docs: http://localhost:8000/docs

### 3 — Process the dataset

**Option A – via browser UI:**
Go to http://localhost:5173 → Setup tab → enter key → Start Processing

**Option B – via command line:**
```bash
cd backend
python process_csv.py
```

Processing ~5 000 messages takes roughly 3–5 minutes (depends on Groq rate limits).

### 4 — Frontend

```bash
cd frontend
npm install
cp .env.example .env            # VITE_API_URL=http://localhost:8000
npm run dev
```

Open http://localhost:5173

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/health` | Health check |

## Deploy to Render + Netlify

### Backend → Render

1. Push this repo to GitHub.
2. Render dashboard → **New → Web Service** → connect repo.
3. Settings:
   - **Root Directory:** `backend`
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `uvicorn main:app --host 0.0.0.0 --port $PORT`
4. Add env var: `GROQ_API_KEY = gsk_…`
5. **For free tier (no persistent disk):** pre-build data locally, commit `backend/data/*.json`, Render loads them at startup.
6. Your URL: `https://conversation-rag-backend.onrender.com`

### Frontend → Netlify

1. Update `netlify.toml` → change the redirect `to` URL to your Render URL.
2. Netlify dashboard → **New site from Git** → connect repo.
3. Auto-detected from `netlify.toml`: base `frontend`, build `npm run build`, publish `dist`.
4. Or via CLI:

```bash
cd frontend && npm run build
netlify deploy --prod --dir=dist
```

## How Topic Detection Works

Uses **sliding-window TF-IDF cosine similarity** (no external API):

1. Build overlapping windows of 10 messages, stride 5.
2. Fit a shared TF-IDF vectoriser (500 features, bigrams, chat stop-words).
3. Compute cosine similarity between each adjacent window pair.
4. If `similarity < 0.48` AND segment is ≥ 20 messages → new topic boundary.
5. Each segment gets a Groq summary + themes list.

## How Retrieval Works

```
Query
  │
  ├─► TF-IDF over checkpoint summaries → top-5 relevant checkpoints
  │
  ├─► TF-IDF over raw 10-message chunks → top-3 verbatim excerpts
  │
  └─► [summaries + chunks + persona] → Groq LLaMA 3.3 → final answer
```

## How Persona Is Built

1. Messages are batched (40 at a time, first 500 messages).
2. Each batch → Groq → partial persona JSON (habits, facts, traits, style, interests, relationships).
3. All partials merged by a final Groq call (de-duplicated).
4. Heuristic stats overlaid (emoji rate, exclamation rate, avg message length).
5. Only explicitly stated facts are included — no guessing.
